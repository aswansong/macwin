# M2 Wave 0 研究报告：虚构软件供应链策略

状态：研究完成，**不进入生产实现**。

## 研究问题

在不联网、不下载、不执行安装包的前提下，是否可以把软件候选的来源、HTTPS、发布者身份、平台签名、哈希、许可证和安全绕过要求，稳定映射成三类用户动作：自动安装（仍需用户确认）、官方入口、阻断。

## 结果

`fixtures.json` 的 8 个虚构候选覆盖了以下路径：

- 全部证据满足：只产生 `auto_install_after_confirmation`；
- Microsoft 365 这类需要人工许可证/账号流程的软件：只给 `official_entry`；
- 缺少签名、哈希、发布者或官方来源证据：只给 `official_entry`；
- 要求绕过 Gatekeeper/SmartScreen：直接 `blocked`；
- 无网：产生 `retry_when_online`，不把“稍后安装”伪报为成功；
- 未勾选：产生 `not_selected`，不执行任何动作。

测试命令：

```bash
python3 -m unittest research/m2-wave0/test_policy.py
```

## 研究结论

1. “官方入口”应当是证据不足时的安全降级，而不是失败或已安装。
2. “自动安装”至少需要官方来源、HTTPS、发布者身份、可信平台签名、可验证哈希和允许自动化的许可证；即使全部满足，也必须先取得用户确认并在真实安装后验证结果。
3. Gatekeeper/SmartScreen 绕过不能降级为官方入口后继续静默处理，应当阻断并解释原因。
4. 网络不可用与用户未选择是两个不同状态，前者可重试，后者保持惰性。

## 明确没有验证的内容

本研究没有验证任何真实软件的来源、签名、哈希、许可证、安装结果或卸载结果；没有读取系统、联网、调用权限、执行命令或安装第三方工具。它不能关闭 OD-007，也不能把 v1 的 `manual_action_required` 改成生产自动安装。真实供应链、发布密钥和更新签名仍受 D-032、D-033、OD-006、OD-007 约束。
