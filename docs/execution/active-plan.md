## 4. 完成定义

M0 只有在以下条件全部满足后才能标为完成：

- 六类指定文档存在且可从 README 导航；
- `feature-list.json` 可被严格 JSON 解析；
- P0 ID、验收 ID、D/E/OD 引用唯一且目标存在；
- Markdown 本地相对链接有效；
- `git diff --check` 无空白错误；
- 仓库中不存在 `.habitpack`、日志、备份、真实 plist/注册表片段、用户名、设备标识或私人绝对路径（仓库路径本身在 D-025 中的记录除外）；
- 仓库中没有应用源代码、原型或安装包；
- GitHub 仓库为 public，默认分支为 `main`，许可证为 MIT；
- 公开页面明确说明当前仅有文档，不声称产品已实现。

## 5. 必须由人拍板的选择

以下改变不能由执行 agent 自主决定：[AGENTS.md、D-024]

- 从文档阶段进入原型、技术预研、开发、Alpha 或公开 Release；
- 新增/移除迁移类别，改变 Windows → Mac、个人文件非目标或正式支持平台；

- 公开品牌、Logo、最终视觉、支持联系方式和市场承诺；
- 代码签名/公证主体、密钥责任和公开发布门槛；

已知待拍板项以 OD-001 至 OD-011 记录在 [`decisions.md`](../product/decisions.md)。

## 6. 执行 agent 可自主决定的技术细节

在不改变已决定行为、数据边界、依赖、权限、默认值和公开承诺时，执行 agent 可以自主决定：

- 仓库内部文件拆分、非公开类型/函数命名和格式化；
- 测试框架、夹具目录和不改变覆盖要求的测试组织；
- JSON schema 校验库、日志库等替代方案的技术比较，但新增生产依赖前仍需负责人拍板；
- 模块内部重构、错误枚举和状态持久化细节；
- CI 的非秘密静态检查与文档链接检查实现；
- 固定安全上限的初始建议值，但改变可接受数据类别或兼容承诺仍需拍板；
- 对完全等价且不改变用户行为的 bug 修复。

遇到文档冲突、平台事实推翻已决定方案或验收无法安全实现时，agent 必须记录证据和选项，请负责人决定；不得静默降低标准。
