# MacWin v1.0.0 真实设备验收手册

状态：待负责人提供设备与签名凭据后执行。本文是操作清单，不代表任何一台设备已经验收通过。

目标范围：Windows 10/11 x64 → Apple 芯片 macOS 15/26，习惯与环境迁移。验收不得搬运个人文件、浏览器书签/历史/密码/Cookie/登录状态、账号、Token、SSH 私钥、项目代码或聊天记录。[D-032、E-021]

## 1. 验收前置条件

一次性准备以下四个环境，并为每个环境记录一个不含设备序列号、用户名或本地路径的短 ID：

| ID | 目标环境 | 必须确认 |
| --- | --- | --- |
| W10 | Windows 10 x64 | 普通用户、UAC 可用、可断网/联网切换 |
| W11 | Windows 11 x64 | 普通用户、UAC 可用、可断网/联网切换 |
| M15 | Apple 芯片 macOS 15 | 新建测试用户或干净快照、可显示 TCC/辅助功能提示 |
| M26 | Apple 芯片 macOS 26 | 新建测试用户或干净快照、可显示 TCC/辅助功能提示 |

同时准备：内置 MacBook 键盘、外接 Windows 键盘、鼠标、触控板；LinearMouse 只作为指针模块的可选官方工具；一个可删除的测试 Wi‑Fi 网络；签名、公证和 updater 测试凭据。不得把真实凭据、密码或私钥写入仓库、日志、报告或 `.habitpack`。

每一项只允许填 `pass`、`fail`、`blocked` 或 `not-applicable`，并附一条可复核的观察结果。没有观察结果不得填 `pass`。

## 2. 每台设备的基础流程

按 `W10 → W11 → M15 → M26` 顺序执行；每台设备从干净快照开始，测试完成后恢复快照，再进入下一台：

1. 安装签名包，核对应用版本、签名、来源和系统架构；首次启动确认不要求账号、不常驻、不自启动。
2. Windows 端执行白名单扫描，只确认浏览器选择/安装与安全偏好、输入设备偏好、系统设置、轻量开发环境和网络名称等声明式项目；确认界面不显示密码、完整路径、序列号或用户名。
3. 导出 `.habitpack`，把包复制到 Mac 的本地临时目录；断网后再次导入，确认核心解析、计划生成和预览仍可用。
4. 在 Mac 端确认迁移计划后执行。计划确认前不得有任何模拟或真实系统更改；执行前必须产生一份迁移前快照。
5. 打开报告和个性化指南，确认结果按 `applied_verified`、`skipped`、`manual_action_required`、`failed_recoverable` 或 `failed_blocked` 表达；Wi‑Fi 密码、访问令牌和其他秘密不得出现在任何输出。
6. 通过设备自检逐模块恢复，再验证恢复后的系统值；最后测试卸载、重新安装和发现原有快照，但不自动覆盖既有快照。

## 3. 必测场景矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| RA-01 | W10/W11 扫描与包导出 | 仅白名单声明式结果；包可离线导入；不含个人文件或秘密 |
| RA-02 | 损坏/篡改包 | 计划确认前阻断；错误不泄露包内容或本地路径 |
| RA-03 | 正常计划与执行 | 计划确认后才改动；每个结果可解释并可在报告中复核 |
| RA-04 | Windows UAC 接受 | 只在标注管理员权限的 Wi‑Fi/系统项出现一次 UAC；授权后仅执行对应模块 |
| RA-05 | Windows UAC 拒绝 | 无提权模块继续完成；网络名称可保留时明确标为降级；密码不得落盘 |
| RA-06 | Mac TCC/辅助功能接受 | 用户逐项授权后仅启用已勾选模块；应用不绕过系统提示 |
| RA-07 | Mac TCC/辅助功能拒绝 | 被拒模块标为跳过或可恢复失败，无关模块继续；提供官方设置入口 |
| RA-08 | 内置键盘 | macOS 原生 Control ↔ Command 四方向按模块生效，重复执行幂等，恢复后精确回到旧值 |
| RA-09 | 外接 Windows 键盘 | 应用前后外接键盘映射不变；插拔/重新连接不会把内置映射套用到外接设备 |
| RA-10 | 鼠标与触控板 | 两者方向分别可验证；断开/重连后不伪报成功；LinearMouse 缺失或拒绝时给官方入口 |
| RA-11 | 软件与开发环境 | 只显示首批白名单；无法安全自动安装的项目为 `manual_action_required`，不伪报安装成功 |
| RA-12 | 无网软件路径 | 无网时核心迁移继续；软件项目标记待处理；恢复联网后可主动重试 |
| RA-13 | 单模块失败 | 失败模块隔离；其他模块结果不回滚、不改写为成功 |
| RA-14 | 选择性取消与恢复 | 取消项为 `skipped` 且没有恢复按钮；“全部恢复”只触碰本次实际应用或可恢复失败的模块 |
| RA-15 | 报告、日志与隐私探针 | HTML/脱敏 JSON 可保存；错误日志只含必要诊断；扫描数据不联网上传 |
| RA-16 | 升级、卸载、重装 | 签名 updater 只在用户确认后安装；卸载不自动删除快照；重装能发现快照并按模块恢复 |

每个 `fail` 必须记录复现步骤、预期与实际结果、应用版本、设备短 ID 和是否可回滚；不要记录密码、SSID、序列号、用户名、绝对路径或完整系统导出。

## 4. 证据目录与脱敏格式

证据只保存到本地临时目录，提交前由负责人逐项删减。推荐文件名：

```text
evidence/
  W10/RA-01-scan.json
  W11/RA-05-uac-denied.json
  M15/RA-09-external-keyboard.json
  M26/RA-16-uninstall-reinstall.json
```

JSON 只允许以下字段：`case_id`、`device_id`、`app_version`、`status`、`observed_at`、`observation`、`artifact_sha256`、`notes`。`observation` 必须是人工脱敏后的短句；禁止写入 Wi‑Fi 密码、SSID、用户名、设备序列号、账号、Token、私钥、绝对路径、完整日志或迁移包原文。

## 5. 签名、公证与发布前门槛

1. Windows 安装包：在干净 W10/W11 上检查代码签名、SmartScreen 结果、安装/升级/卸载和安装后架构。
2. macOS DMG/App：在 M15/M26 上检查 Developer ID 签名、notarization、stapling、Gatekeeper 首次打开和卸载后残留策略。
3. updater：使用正式公钥和隔离的签名私钥完成一次检查、用户确认、下载、签名校验和回滚演练；`PENDING_RELEASE_KEY` 不得进入正式发布。
4. 负责人复核 `docs/product/v1-validation.md`、本手册所有 `RA-*` 结果、变更说明和资产哈希后，才允许合并 `main`、创建 `v1.0.0` 标签和 GitHub Release。

签名凭据、真实设备、系统弹窗和最终公开 Release 属于人类门槛；缺任何一项都保持 `blocked`/`not-applicable`，不得用本地构建或 CI 结果替代。[D-032、D-033、E-021、E-023]
