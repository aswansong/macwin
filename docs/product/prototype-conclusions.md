# M1 可点击原型结论（第二版加固）

状态：M1 可丢弃交互验证；M2 Wave 0 已获局部研究授权，但本归档不是生产实现、真实设备验证或新的系统能力承诺。[D-024、D-029、E-018]

## 本轮回答的问题

本轮没有恢复第一轮的 8 步流程，而是检验精简后的两端流程能否在保留安全边界的同时完整处理选择、拒绝、失败、重试和恢复：

- 首页只有 Windows 检测和 Mac 导入两个入口；
- Windows 只显示“检测、选择、导出”，Mac 只显示“导入、确认、完成”；
- 扫描结果直接按“操作习惯、软件与开发、系统设置、Wi‑Fi”展示具体发现项；
- 选择项采用单行信息结构，说明和风险标识直接可见；
- Mac 计划仍不可跳过，可取消模块，并先模拟验证迁移前快照；
- Windows 和 Mac 上的选择会继续影响计划、结果、报告、指南和恢复入口；
- “操作习惯”保持一个用户模块，但内部按内置键盘 Ctrl、外接 Windows 键盘 Ctrl、鼠标与触控板滚动三个动作分别报告和恢复。[D-006、D-007、D-010、D-012、D-026]

## 已否定并删除的方案

- **全局 8 步进度**：把两台电脑和内部状态混成一条长流程，增加心理负担。
- **扫描统计和排除原因入口**：数字与不能处理的项目没有帮助用户完成当前任务。
- **重复的选择状态与详情入口**：“已选择/未选择”“查看细节”和卡片式问卷重复表达复选框本身。
- **Windows 与 Mac 重复确认常用软件**：常用软件只在 Mac 强制计划中确认一次；Windows 选择页不再重复询问。
- **通用异常重试**：第三方工具拒绝或权限拒绝不能被一个通用“重试”直接改写成成功；只有无网或明确人工待处理项提供重试。
- **对所有成功模块提供恢复按钮**：不可自动恢复的软件、开发工具和不修改系统的指南不再显示无效恢复操作。

## 当前采用的原型假设

- 首页两个入口已经足以区分“我在旧 Windows”与“我已经在 Mac”。
- Windows 选择页使用 6 个动态选项：内置键盘 Ctrl、外接 Windows 键盘、指针、轻量开发环境、Wi‑Fi 密码和个性化指南；常用软件转到 Mac 计划一次确认。安全常用项预选，开发环境和 Wi‑Fi 密码保持未选。[D-006、D-019、D-020]
- Homebrew 不在 Windows 默认选项中；仅当用户主动选择开发环境并在 Mac 计划中展开说明后，才可再次单独勾选，默认仍为未选。[D-006、D-020]
- 计划用模块单行结论承载默认信息，原因、收益、例外、权限、验证和恢复按需展开；敏感、管理员、第三方和不可自动恢复标识保持首层可见。[D-010、D-011、D-019]
- Windows 端预选指针习惯不构成第三方安装同意。Mac 强制计划页在确认按钮前单独展示 LinearMouse 候选的名称、用途、候选来源、版本策略、许可证入口、所需权限、常驻可能性、已知冲突或兼容性影响和停用/卸载影响；尚无证据的技术值全部明确标为“待 M2 / OD-007 验证”，不虚构版本、网址、许可或冲突结论。控件默认未勾选，不确认仍能继续。[D-010、D-011、OD-007]
- LinearMouse 决策显式区分 `unconfirmed`、`confirmed` 和 `declined`；只有先确认后在执行前拒绝，才能进入 `declined`。未确认或确认后拒绝都只把指针动作标为 `manual_action_required`，并把精确原因带到完成页、报告、指南与恢复状态；Ctrl 动作继续按辅助功能权限结果处理。一个模块内混合成功与待处理时显示“部分完成”，全局不能显示全部成功。[D-014、D-026]
- 报告和指南只生成已确认模块的内容；恢复后，报告与指南显示“已恢复”而不是继续显示迁移成功。[D-012、D-015、D-026]
- 恢复页仍只有一个“操作习惯”入口，但只恢复其中曾经 `applied_verified` 且可恢复的动作；权限跳过和第三方待处理动作不会变成“已恢复”。[D-012、D-026]
- 无网软件可重试；UAC、Mac 权限和第三方拒绝只降级依赖模块，其他模块继续。[D-014、D-016、D-026]

这些仍是待真实目标用户验证的交互假设，不等于写入正式产品的最终决定。

## 本轮原型验证记录

2026-07-30 在本机浏览器中对第二版基础流程实际点击验证：

- Windows 检测、选择、导出和 Windows → Mac 交接；
- 首页直接进入 Mac 导入、强制计划确认和正常完成；
- UAC 拒绝后仅迁移网络名称且迁移包不含密码；
- Mac 权限拒绝、无网软件待重试、第三方工具拒绝和单模块失败隔离；
- 损坏迁移包在计划生成前阻断；
- 按模块恢复、全部恢复，以及恢复状态同步到报告和指南；
- Windows 取消习惯项和 Mac 取消软件模块后，计划、报告和指南同步删除无关内容；
- 1280×720 桌面、390×844 窄窗口和 200% 文字缩放；页面无横向溢出，原型控制在窄窗口不遮挡内容；
- 原生按钮、复选框和下拉框具备可见键盘焦点；浏览器控制台无警告或错误；页面资源只来自本机开发服务器。

2026-07-31 的本轮加固由自动化状态与共享渲染输出测试覆盖强制计划、LinearMouse 默认未确认与独立确认、三个操作习惯动作、选择联动、UAC/权限/离线/第三方/失败、损坏包、重试和动作级恢复；生产构建通过。同日使用本机 Vite 与受控浏览器实际复验：正常场景确认候选工具后全部完成；第三方拒绝场景分别实点“从未确认直接继续”和“先确认、再拒绝”，两条路径的权限页按钮、完成页、报告与指南使用互斥且一致的精确原因；Mac 权限拒绝只跳过两个 Ctrl 动作；动作级恢复会同步更新主页、报告和指南。390×844 窄窗口与 200% 文字缩放组合下，含长原因的完成页仍无横向溢出，原型控制保持普通文档流，不遮挡正文；浏览器控制台无警告或错误，观察到的七个页面资源全部来自 `127.0.0.1` 本地 Vite 服务。以上都不构成真实设备产品测试。[D-023]

## M1 原型与格式资产的状态边界

冻结原型分支本身只证明使用虚构数据的浏览器交互、状态联动和失败/恢复表达，不证明真实系统能力；整体 M1 已在 `main` 完成严格 `1.0.0` 格式档案，包括 `.habitpack` 事实源、JSON Schema、虚构夹具、哈希与路径拒绝规则及统一校验命令。OD-011 仅继续阻塞未来兼容窗口和对外承诺，不回溯否定已完成的 M1 格式验证。M2 Wave 0 只允许隔离研究和虚构夹具，不改变本归档的产品边界；本轮原型交互结论是否进入正式产品，以及真实平台 R2 其余部分，仍需负责人拍板。OD-007 未关闭前，候选来源、版本锁定、签名/哈希、许可证、权限、常驻方式和卸载/恢复行为都不能进入生产下载或安装。[D-024、D-027、D-028、D-029、E-017、E-018、OD-007、OD-011]

## 未验证的真实能力与安全边界

原型没有读取或修改 Windows/macOS 设置、注册表、Wi‑Fi 密码、真实软件或个人数据；没有请求 UAC、TCC 或管理员权限；没有安装 Karabiner-Elements、LinearMouse、Homebrew 或任何软件；没有外部网络请求、外部 API、账号、后端、数据库、原生桥接、Shell、PowerShell、自动更新、真实快照、真实恢复、安装包或 Release。它不会生成或导入真实 `.habitpack`。

OD-005 继续阻断真实 Wi‑Fi 凭据实现；OD-006、OD-007 继续阻断生产更新和第三方下载。只有负责人确认结论并授权下一阶段后，才能开始技术预研或生产实现。[D-019、D-024]
