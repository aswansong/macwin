# MacWin 视觉系统 v3 验收与精修记录

## 范围

v3 从 `prototype/visual-system-v2` 的 `3b3c86611a5de645b5a0bb8744a52ffb8b151c49` 开始，只处理浏览器原型的视觉状态切换、滚动位置、移动端信息提示和响应式表现。迁移规则、Tauri 命令、权限语义、快照/恢复逻辑与数据结构没有改动。

## 三轮走查

### 第 1 轮：基线验收

- 真实浏览器走查 Windows W1→W2→W3、Mac B→C2→C4，以及报告、指南、恢复页面。
- 检查 1440×900、1280×720、390×844；确认没有横向溢出，开发预览资源没有外部请求，控制台没有 warn/error。
- 发现：从 W1 点击“开始检测”或从 Mac 封面点击“导入迁移包”后，浏览器会保留旧按钮的滚动位置。移动端因此可能直接落在新页面中段，跳过标题和当前步骤。
- 发现：移动端 C 地图默认只显示圆点，当前步骤缺少文字锚点。

### 第 2 轮：最小修复

- 在渲染层记录上一次视图，只在视图真正切换时把页面滚动到顶部；同一页面内勾选模块不会被强制拉回顶部。
- 移动端 C 地图保留当前步骤文字，其余步骤仍保持紧凑圆点布局，避免增加页面高度和认知负担。
- 复跑 `npm test`、`npm run build`、`git diff --check`，均通过。

### 第 3 轮：回归验收

- 验证页面切换后 `scrollY = 0`，移动端地图显示当前“确认计划”等语义文字。
- 验证正常完成、UAC 拒绝后的 Wi‑Fi 降级、Mac 权限拒绝、离线、第三方工具拒绝、单模块失败、损坏迁移包、选择取消和按模块恢复。
- 验证报告、指南、恢复入口的返回路径和独立状态；确认每个异常结果仍按模块展示，不用总成功覆盖失败/待处理。
- 在 1280×720、390×844 检查 `scrollWidth === clientWidth`；生产预览确认没有 `.preview-toolbar` 开发控件。
- 再次检查控制台和资源引用：无 warn/error、无未授权外部资源。

## 未验证与保留事项

- 这是浏览器虚构数据原型；没有读取或修改真实 Windows/macOS 设置，没有执行 UAC/TCC、第三方工具安装、Homebrew、Wi‑Fi 凭据写入或真实恢复。
- 200% 系统文字缩放仍应在真实桌面构建和原生窗口中做最终人工验收；本轮已覆盖窄桌面与移动布局及键盘焦点路径。
- v3 不改变未决产品决定，也不代表签名、公证、安装包或 Release 已完成。
