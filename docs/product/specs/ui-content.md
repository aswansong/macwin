# 界面与内容规格

## 1. 信息架构

第一版只有两种主要形态：[D-021]

- **首次向导**：兼容检查、扫描、问卷、导出或导入、计划、权限、执行、验证和完成。
- **迁移后主页**：当前结果摘要、待处理项、个性化指南、导出报告、检查更新、重试和恢复。

MacWin 不常驻、不自启动。主页只在用户主动打开时读取本地状态。[D-012]

## 2. Windows 向导页面

### W-01 欢迎

必须在首屏可见范围说明：

- “把习惯与环境带到 Mac，不搬个人文件”；
- “扫描只在本机进行”；
- 支持平台；
- 下一步会扫描哪些类别。[D-002、D-008、D-017]

### W-02 扫描结果

按“键盘与输入、鼠标、软件、开发、Wi‑Fi”分组。每组显示发现数量、可迁移数量、排除数量和排除原因入口。不得只给一个不透明总分。[D-005、D-026]

### W-03 动态问卷

约 5 个勾选项，无文字输入。每项包含结果标题、单句收益、默认状态和“查看细节”。高权限、含秘密或安装开发依赖的项目使用固定标识并默认不勾选。[D-006]

Wi‑Fi 密码选项旁必须直接显示“迁移包第一版不加密”，不能藏在条款或二级页面。[D-009、D-019]

### W-04 最终确认与导出

显示将包含/排除的模块、是否含秘密、是否已用管理员权限和迁移包保存位置。完成后给出传输安全提醒；不提供自动云上传。[D-008、D-019]

## 3. Mac 向导页面

### M-01 导入

允许选择 `.habitpack`。校验期间不得读取后立即改设置。错误必须区分“文件损坏/不安全”“版本不兼容”“来源平台不支持”和“部分规则当前不适用”。[D-017、D-027]

### M-02 迁移计划

计划页是不可跳过的核心页面。[D-010]

每个模块卡片（这里的“卡片”是信息组，不要求视觉卡片墙）必须显示：

- **会改变什么**：用户可识别的目标状态；
- **为什么**：与来源习惯或用户选择的关系；
- **好处**：具体任务差异，例如“在普通编辑框继续用 Ctrl+C”；
- **例外/代价**：如终端仍使用真实 Ctrl、第三方工具需要常驻；
- **需要你做什么**：系统授权、管理员密码或软件登录；
- **怎么恢复**：自动恢复、人工恢复或不可恢复；
- **怎么确认成功**：执行后的检查方式。[D-010、D-011、D-014、D-015]

用户确认按钮必须总结动作数、第三方安装数、权限数和是否包含秘密；不得使用模糊的“全部优化”。

### M-03 权限引导

在触发系统弹窗前，用同一术语解释权限名称、哪个模块需要、拒绝后的降级结果。系统仍逐项请求，MacWin 不绘制仿冒系统授权框。[D-014]

### M-04 执行与验证

按模块显示状态，而不是只显示单一旋转动画。允许无依赖模块并行属于实现细节，但 UI 必须保持可理解的动作顺序和最终状态。[D-026]

显示状态只使用：等待、正在处理、已验证、已跳过、需要手动完成、失败可恢复、状态未知。禁止把“命令已运行”显示为“已完成”。

### M-05 完成

顶部结论必须从模块状态推导：

- 全部验证：迁移完成；
- 有跳过或人工动作：已完成，还有项目待处理；
- 有失败或未知：部分未完成，可重试或恢复。[D-026]

含秘密的包必须再次提示删除不再需要的副本，但删除动作必须明确目标且由用户确认。[D-019]

## 4. 迁移后主页

主页只保留：

- 最近一次迁移状态和日期；
- 待处理/可重试项目；
- “我的 Mac 使用指南”；
- 导出报告；
- 按模块恢复/全部恢复；
- 检查更新；
- GitHub 和待确定的自媒体入口。[D-012、D-015、D-016、OD-001]

不得加入常驻系统监控、账号、信息流、聊天机器人或促使用户长期运行的后台功能。[D-008、D-012]

## 5. 报告内容

可导出报告至少包含：

- 应用与规则版本；
- 来源/目标平台的大版本和架构，不含设备序列号；
- 用户确认的模块；
- 每个动作的“之前（非秘密摘要）/计划/结果/验证状态”；
- 为什么迁移以及具体收益；
- 权限拒绝、跳过、人工动作和错误类别；
- 恢复入口与备份存在状态。[D-015、D-026]

报告不得包含 Wi‑Fi 名称/密码、用户名、绝对路径、Token、账号、原始注册表/plist 或稳定设备标识。[D-019]

具体导出格式由 OD-010 决定；执行 agent 可在不改变数据边界的前提下比较 HTML、PDF 或 Markdown，再由负责人确认用户可见格式。

## 6. 个性化指南文案

内容必须与实际计划和结果绑定：未安装 Homebrew 就不展示卸载 Homebrew 教程；Ctrl 兼容被跳过就不能说“现在可以继续用 Ctrl”。[D-015、D-026]

指南解释 Mac 优势时使用条件化表述，例如：

- 对重视外出使用的人，Apple 芯片 MacBook 的能效与软硬件整合可能减少充电和待机管理负担；
- 对轻量开发，macOS 的 Unix 工具链和常见开发工具生态可减少部分环境差异；
- 触控板、睡眠唤醒和 Apple 设备协同可能更顺手；
- 但专用 Windows 软件、游戏、企业系统或外设仍可能更适合留在 Windows。

不得写“Mac 在所有方面优于 Windows”或使用无法验证的具体续航/性能数字。

## 7. 视觉与动效约束

已决定的方向：[D-021]

- 大面积浅色留白；
- 2–4 种协调亮色只用于模块层级、状态和引导；
- 适度圆角、清晰文字层级、轻量反馈动效；
- 可信、友好、克制、接近原生；
- 品牌幽默只出现在欢迎、空状态或完成庆祝，不用于权限、密码、恢复和错误。

禁止：全屏渐变、霓虹赛博、重毛玻璃、密集卡片墙、深色底 + 荧光绿的通用 AI 风格。[D-021]

这些方向不能替代验收。视觉原型必须另外验证：

- 文字在 200% 缩放下不被截断；
- 所有交互可用键盘完成，并有可见焦点；
- 状态不只靠颜色表达；
- 默认中文文案不溢出；
- “含秘密”“需管理员”“不可自动恢复”在不展开细节时仍可见；
- `减少动态效果` 开启时非必要动效停用。

具体色值、字体、Logo 和时长属于 OD-004，当前不能伪装为定稿。

## 8. 语言与术语

第一版简体中文优先，界面架构使用消息 key，不把用户文案散落在规则逻辑中；当前不要求完整英文翻译。[D-021]

首次出现时解释：

- **Homebrew**：macOS 常用命令行软件包管理器；
- **迁移前快照**：MacWin 改动前保存的相关设置副本，不是整机备份；
- **Command / Option / Fn**：保留键帽名称，并用中文解释用途；
- **规则包**：更新“如何识别和转换设置”的离线文件，不含用户迁移数据。

安全文案使用具体动词“读取、保存、安装、修改、删除、恢复”，避免“优化、增强、智能处理”等掩盖实际动作的词。
