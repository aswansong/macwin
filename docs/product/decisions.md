# 产品决策记录

最后更新：2026-08-03

状态说明：

- **已决定**：负责人已明确拍板，执行 agent 必须遵守。
- **临时决定**：当前可据此规划，但进入相关开发前需要复核。
- **未决定**：不能据此作公开承诺或实现不可逆选择。
- **已取代**：保留追溯，不再约束当前方案。

## 已决定

### D-001：产品身份

- 状态：已决定
- 决定：产品名为 **MacWin**，中文短句为“把 Windows 习惯带到 Mac”。`.habitpack` 是迁移文件扩展名。
- 理由：名称易传播，并保留适量品牌幽默；安全、权限和错误场景不使用玩笑弱化风险。
- 证据：E-015

### D-002：第一版方向、范围与非目标

- 状态：已决定
- 决定：第一版只做 **Windows → Mac** 的“习惯与环境迁移”。不做 Mac → Windows，不搬个人文件，不克隆完整系统，不迁移账号会话、企业受管配置或硬件绑定状态。
- 理由：把工程和安全边界限制在可解释、可回滚的偏好迁移。
- 证据：E-011、E-012、E-013、E-015

### D-003：开源与分发入口

- 状态：已决定
- 决定：采用一个公开 GitHub 仓库、MIT License、同一产品和同一代码库；未来由 GitHub Releases 提供 Windows 与 macOS 两个平台安装包。
- 理由：源码、规则、发布记录和问题跟踪集中维护。
- 证据：E-015

### D-004：默认迁移理念

- 状态：已决定
- 决定：默认采用“平衡迁移”：优先保留高频 Windows 肌肉记忆，同时保留合理的 Mac 原生逻辑；不把 Mac 全面伪装成 Windows。
- 理由：降低上手成本，又避免长期被不兼容的全局改造锁住。
- 证据：E-001、E-005、E-009、E-010、E-015

### D-005：P0 模块

- 状态：已决定
- 决定：P0 包含兼容性检查、Windows 扫描与问卷、`.habitpack` 导出、Mac 计划预览、迁移前快照与按模块恢复、键盘与输入、鼠标与触控板、软件环境、可选轻量 AI 开发环境、经明确选择的个人 Wi‑Fi、验证报告和个性化指南。
- 理由：覆盖负责人已观察的高频迁移成本。
- 证据：E-001、E-003、E-004、E-007、E-015

### D-006：扫描与确认问卷

- 状态：已决定
- 决定：Windows 端仅按白名单自动检测，再展示约 5 个动态勾选题，不要求文字输入。安全且普适的建议可预选；Wi‑Fi 密码、管理员权限、AI 开发环境和 Homebrew 等敏感或高成本项必须显式确认。
- 理由：减少新手决策负担，同时保留对敏感行为的有效同意。
- 证据：E-015

### D-007：选择性 Ctrl 兼容

- 状态：已决定
- 决定：不做全局 Ctrl/Command 交换。对常用编辑快捷键提供选择性 Ctrl 兼容；Command 保持可用；终端、VS Code 集成终端、远程桌面和虚拟机等场景保留真实 Ctrl。Caps Lock 可用于输入法切换；Option 和 Fn 默认只解释、不重映射。内置键盘和外接 Windows 键盘分别识别和配置。
- 理由：解决首要痛点，又避免破坏依赖真实 Ctrl 的场景。
- 证据：E-001、E-002

### D-008：本地、无账号、默认零上传

- 状态：已决定
- 决定：核心扫描、导出、导入、计划、执行、验证和恢复全程可离线，不依赖账号或大模型。除版本/规则更新检查外默认不联网；更新检查不得上传扫描结果、设备清单或迁移包。
- 理由：系统设置和密码迁移要求清晰的数据边界。
- 证据：E-015

### D-009：迁移包格式与数据最小化

- 状态：已决定
- 决定：`.habitpack` 使用自定义扩展名和标准 ZIP 容器。第一版不加密。只收录规则明确需要的注册表或配置原始片段，不导出完整注册表或整套个人配置；用户名、本地路径和设备信息仅在规则无法表达时收录，设备序列号默认不收录。
- 理由：保持可调试与跨平台，同时缩小隐私和攻击面。
- 证据：E-002、E-010、E-011、E-015

### D-010：强制计划预览与确认后自动化

- 状态：已决定
- 决定：Mac 端应用任何更改前，必须生成并展示迁移计划，列明动作、原因、收益、权限、第三方工具、失败影响和回滚方式；用户确认后，除系统强制交互和身份验证外尽可能自动执行。
- 理由：把“省事”和“知情”同时设为产品原则。
- 证据：E-006、E-014、E-015

### D-011：第三方工具

- 状态：已决定
- 决定：可以使用经过审核的第三方工具；当前候选包括 Karabiner-Elements 和 LinearMouse。安装前必须展示名称、用途、来源、所需权限和卸载影响，并由用户确认。
- 理由：系统原生能力不足时不重复造轮子，但不能静默引入高权限依赖。
- 证据：E-002、E-003、E-015

### D-012：快照、恢复与应用生命周期

- 状态：已决定
- 决定：应用前保存一份迁移前快照，支持按模块恢复或全部恢复到“迁移前状态”，不宣称恢复出厂设置。MacWin 不常驻、不自启动；备份放在应用包外，删除并重装应用后仍可发现并恢复。
- 理由：一份清晰基线比维护多份复杂历史更适合第一版。
- 证据：E-003、E-014、E-015

### D-013：软件环境迁移

- 状态：已决定
- 决定：扫描已知软件并匹配 macOS 版本；由用户勾选后，能安全自动安装的项目自动安装，其余只提供官方入口。普通应用安装当时的最新稳定版；开发运行时优先匹配主版本。浏览器按 D-018 单独限制。
- 理由：迁移“选择和环境”，不搬运 Windows 二进制或不可信安装器。
- 证据：E-004、E-007、E-015

### D-014：权限模型

- 状态：已决定
- 决定：Windows 默认普通权限扫描；需要管理员权限的选项必须标注，用户选择后尽量合并为一次 UAC，拒绝则跳过依赖项。Mac 端集中解释权限，但遵守系统逐项授权；拒绝后只降级相关模块，继续其他模块。不得绕过平台安全机制。
- 理由：最小权限，同时尽可能减少用户重复操作。
- 证据：E-006、E-015

### D-015：指南、报告与错误反馈

- 状态：已决定
- 决定：迁移后生成个性化 Mac 使用指南和可导出报告，说明配置了什么、改变了什么、为什么、收益和恢复方式。错误时生成本地脱敏日志，并展示 GitHub Issues；负责人自媒体只有在明确提供并拍板后才展示，v1 不展示未提供的自媒体链接。第一版不自动上传日志，也不要求用户在应用内提交。
- 理由：迁移不是黑盒；支持入口应简单且不扩大隐私范围。
- 证据：E-004、E-005、E-008、E-009、E-010、E-015

### D-016：更新方式

- 状态：已决定
- 决定：联网时可自动检查 GitHub Releases，用户也可主动检查；支持离线导入规则包。只有用户确认后才安装更新。第一版只提供标准版，不维护单独离线安装版；无网时跳过额外软件下载并允许稍后重试。
- 理由：兼顾大多数联网用户和核心离线迁移能力。
- 证据：E-015

### D-017：正式支持平台

- 状态：已决定
- 决定：第一版正式支持 Windows 10/11 x64 来源端，以及运行 macOS 15 或 26 的 Apple 芯片 Mac 目标端；其他架构和系统标记为不支持或实验性，不得默认继续执行。
- 理由：控制首发测试矩阵。
- 证据：E-015

### D-018：浏览器边界

- 状态：已决定
- 决定：浏览器模块只处理浏览器选择、安装和经白名单批准的安全偏好；不迁移书签、历史、密码、Cookie、扩展登录状态或用户配置目录。
- 理由：避免把习惯迁移扩展成个人数据和会话迁移。
- 证据：E-008、E-013、E-015

### D-019：个人 Wi‑Fi 与密码

- 状态：已决定
- 决定：仅迁移用户逐项选择的 WPA/WPA2/WPA3 个人网络。排除企业 802.1X、证书网络和受管网络。选择密码迁移时允许一次 UAC；迁移包必须声明 `contains_secrets`，界面、报告、日志、错误和回滚快照不得显示或保存密码。目标端只把密码写入系统网络/钥匙串，临时明文立即清理，成功后提示删除迁移包。拒绝提权时可降级为仅迁移网络名称。
- 理由：负责人将方便性置于迁移包加密之前，同时同意强制的敏感数据护栏。
- 证据：E-014、E-015

### D-020：轻量 AI 开发环境与 Homebrew

- 状态：已决定
- 决定：开发模块仅在检测到相关工具或用户选择时推荐，默认普通用户不安装。历史候选范围曾包括 GitHub CLI、uv、Jupyter、Ruff、常用编辑器扩展和 `Projects` 目录；v1.0 首批可识别目录由 D-034 锁定，未列入其中的工具暂不进入正式扫描或迁移包。Docker、Ollama 等重型工具不在默认范围。Homebrew 是 macOS 命令行软件包管理器，只在开发场景按需选择，并在安装前解释用途和影响。
- 理由：支持轻量 AI 编程，不把 MacWin 变成通用开发机镜像工具。
- 证据：E-007、E-015

### D-021：产品界面、语言与视觉方向

- 状态：已决定
- 决定：采用“首次向导 + 迁移后简洁主页”。第一版简体中文优先，架构预留多语言，不承诺完整英文 UI。视觉应可信、克制、接近原生、明亮友好且有探索感；大面积浅色留白，以 2–4 种协调亮色建立层级，使用适度圆角和轻量动效。禁止全屏渐变、霓虹赛博、重毛玻璃、密集卡片墙及深色底配荧光绿的通用 AI 风格。
- 理由：符合目标用户的上手场景和负责人审美。
- 证据：E-015

### D-022：预期技术架构

- 状态：临时决定
- 决定：正式实现拟采用 Tauri 2、TypeScript UI、Rust 核心、平台适配器和声明式 JSON 规则。进入开发前必须通过技术预研复核，不能因本决定跳过再次授权。
- 理由：兼顾双平台界面复用、本地系统能力、包体与安全边界。
- 证据：E-015

### D-023：Alpha 与公开发布门槛

- 状态：已决定
- 决定：源码立即公开；未签名安装包只给明确知情的 Alpha 测试者。面向普通新手发布前必须完成 macOS 签名与公证、Windows 可信签名/分发，并通过真实 Windows 10、Windows 11 和 Apple 芯片 Mac 的验收矩阵。执行完成不等于结果有效，必须验证用户可观察结果。
- 理由：系统配置工具不能把平台警告和命令返回码当成发布质量。
- 证据：E-006、E-012、E-015

### D-025：仓库位置

### D-026：失败隔离与可验证性

- 状态：已决定
- 决定：模块之间必须隔离失败；一个模块失败不得自动回滚或阻断已获用户确认且无依赖的其他模块。每个动作必须输出成功、跳过、失败或需人工完成的状态，并用结果检查验证，不能只记录命令已执行。
- 理由：目标环境会漂移，平台权限和第三方安装也可能部分失败。
- 证据：E-006、E-012、E-014、E-015

### D-027：声明式安全边界

- 状态：已决定
- 决定：迁移包不得携带可执行脚本或任意命令；导入内容只能匹配应用内已知规则 ID、已知字段和白名单目标。路径、参数和压缩内容必须验证，绝不拼接执行包内字符串。
- 理由：避免公开格式变成跨设备任意代码执行通道。
- 证据：E-002、E-015

### D-028：接受冻结的 M1 第二版原型结论

- 状态：已决定
- 决定：追认 `prototype/ui-flow-v2-hardening` 的冻结提交 `37edc4edd52f2d0fb5aa7d796faa5fd7437bbb75` 为最终 M1 交互原型，并接受其紧凑的两端三阶段流程、首层扫描结果精简、常用软件只在 Mac 计划确认一次、LinearMouse 独立知情确认、动作级部分成功以及报告/指南/恢复联动结论。原型继续与 `main` 隔离；该接受不引入生产依赖、技术架构或任何真实系统能力。
- 理由：第二版已经独立复核并获负责人接受，能够作为交互证据归档，同时不越过 M1 的虚构浏览器交互边界。
- 证据：E-017

### D-029：M2 Wave 0 仅限研究授权

- 状态：已决定
- 决定：负责人授权 M2 Wave 0 研究型执行：`main` 只更新授权与执行计划文档并可提交推送；研究代码、虚构夹具和报告只能在 `codex/m2-*` 独立研究分支编写、测试、提交和推送，禁止 PR、合并 `main` 和 Release。允许 M1 `.habitpack` `1.0.0` 独立 parser、一次性 Tauri 2 最小壳与 mock bridge、模拟快照/恢复、离线签名与供应链虚构测试；允许受限 HTTPS 阅读官方文档和在隔离环境安装锁定版本的开发验证依赖。
- 边界：不授权真实设备、真实秘密、权限调用、系统设置读写、Wi‑Fi 密码、Karabiner/LinearMouse/Homebrew/系统服务/应用包实际安装、生产依赖、生产骨架、Alpha 或 Release。15 个 P0 继续为 `specified`；需要真实设备、真实秘密、第三方实际安装、生产签名密钥或产品边界变化时，立即停止对应研究流。主控可见可用额度低于 20% 时停止派发新任务并保留目标；该门禁不是产品状态，不能用 `goal complete` 或 `blocked` 伪装暂停。
- 理由：先用可隔离、可复现的研究证据降低格式、桥接、恢复和供应链风险，同时不把研究结论误写成真实平台或生产能力。
- 证据：E-018

### D-030：Alpha 0.1 Windows → Mac 纵向切片授权

- 状态：已决定
- 决定：负责人接受 M1 原型方向，并授权在独立分支 `alpha/v0.1-vertical-slice` 实现一个可运行的本地 Alpha 纵向切片。允许真实读取 Windows 白名单习惯与环境、生成和导入现有 `.habitpack` 1.0.0、在 macOS 上按强制计划执行声明式 Finder 扩展名和键盘重复速率设置、保存一份迁移前快照、按模块验证与恢复，并生成报告和指南。实现必须保持无账号、默认零上传、不执行包内命令；普通权限优先，系统要求的权限由系统逐项处理。
- 边界：本轮明确不实现 Wi‑Fi 或密码、Ctrl/Command 兼容层、第三方工具安装、Homebrew、软件自动安装、UAC/TCC/管理员授权流程、真实秘密、更新、安装包签名、公证、公开 Release 或个人文件搬运。浏览器/软件只作为白名单检测与官方入口提示，不读取历史、书签、密码、登录状态或应用数据。
- 理由：用最小真实纵向切片验证扫描—导出—导入—计划—应用—恢复的系统边界，同时把高风险和未决供应链/凭据能力留在后续决策门内。
- 证据：E-019

### D-031：Alpha 0.2 真实 Mac 与选择性 Ctrl 授权

- 状态：已决定
- 决定：负责人接受 Alpha 0.1 原型与纵向切片，并授权在独立分支 `alpha/v0.2-keyboard-compatibility` 完成研究型 M2 Wave 0 的下一步真实闭环：在 Apple 芯片 Mac 上真实读取、写入、验证和按模块恢复 Finder 扩展名与键盘重复速率；检测内置/外接键盘并允许独立选择；只对固定 Ctrl 白名单在普通应用中转换为对应 Command，终端、远程桌面、虚拟机、Warp、iTerm2、Terminal 和 VS Code 保留真实 Ctrl；允许使用 Karabiner-Elements，但只做用户确认后的固定规则、结构化合并、备份、原子替换和只删除 MacWin 自己的规则。不得静默安装第三方工具、执行包内命令、实现 Wi‑Fi/密码/个人文件/软件自动安装/更新/签名分发或创建 Release。
